# 音频助手：完整产品与开发约束

本文件是 2026-11-14 用户重启需求的长期权威记录，按主题完整整理。不得从旧代码反推需求；新会话先读本文件、其余五份长期文档和 Git 状态。旧版曾有 UI 混乱、波形异常、操作复杂和页面过长问题，本次从产品和结构重新开发。

## 0. 重启与仓库

旧仓库 GZR-zhuanjia/AudioAssistant；用户原指定新仓库 GZR-zhuanjia/AndriodAudioEditor。阶段 3 推送时 GitHub 明确提示已更名为 GZR-zhuanjia/AndroidAudioEditor，当前交付使用这个正式地址，原历史保留。先检查仓库结构、分支和 Git 状态。旧 UI 与导航不沿用；确有价值的底层代码经检查才可复用。空项目可新建，保留所有历史，不无意义全仓重写、不强推、不随意删除重要源码。

## 1. 定位与平台

应用暂名“音频助手”，仅供一人日常离线处理音频，简单、直观、可靠，可靠性优先于功能数量。核心模块仅视频转音频、音频裁剪与拼接、成果库。

Android 13+，minSdk 33，targetSdk 优先 36，arm64-v8a，兼容 16 KB 内存页。完全中文、现代 Material 3，跟随系统深浅色；常用按钮明确易操作，不专门设计适老化大字体。无网络处理、账号、服务器、云同步、广告、遥测或在线分析。

## 2. 技术与架构

Kotlin、Jetpack Compose、Material 3、Navigation Compose、Media3 ExoPlayer、Coroutines / Flow、Kotlinx Serialization、Android NDK、JNI / C++、自行精简编译 FFmpeg、LAME MP3、Gradle Kotlin DSL。

禁止停更的原版 FFmpegKit、外部服务器处理、不存在的第三方 API、伪造 .so、假音频实现及仅改扩展名冒充转码。使用稳定且相互兼容的版本，记录实际选择的工具和依赖版本，保留 NDK 构建脚本和开源许可。所有第三方原生库均考虑 16 KB 页兼容。

架构为 UI → ViewModel → Repository / Service → Native Audio Engine，保持清晰，不为形式拆分大量模块。

## 3. 首页与导航

首页以两张功能卡片为主：“视频转音频”“音频裁剪与拼接”；有最近项目时可显示“继续上次剪辑”。点击卡片进入模块，不直接弹文件选择器。

底部四入口：首页、视频转换、音频剪辑、成果库。首页卡片与底部导航进入同一模块和同一状态，不创建独立页面状态。切换时保留歌曲列表、所选视频和进行中操作。

单曲裁剪器为全屏，隐藏底部导航，返回时自动保存编辑。歌曲列表独立滚动，底部关键操作固定，不将全部按钮堆成长页面；操作使用适量面板而非每个操作新开全屏。提供空、加载、成功、错误状态。

## 4. 视频转音频

### 导入与队列

“从相册选择”用系统 Photo Picker，仅视频，单选和多选，不申请整个相册读取权限。“从文件中选择”用 SAF，单个或多个视频。两入口可连续添加到同一待处理列表，可继续添加，不为各文件建立页面。

队列逐项展示名称、时长、可获取的文件大小、当前状态、转换进度、移除。

### 转换与命名

默认真正输出 MP3，使用 LAME 编码。若原视频中已含兼容 MP3 音轨且无需改变音频数据，优先复制音频流。支持批量、单文件进度、整体进度、取消、单文件失败重试、完成结果管理。取消清理未完成文件，保留成功成果。

开始转换前弹 Material 3 Bottom Sheet。单文件默认名称为原视频去扩展名，允许修改，默认 MP3；批量在一个面板列出全部名称，分别重命名，不连续弹多个对话框。成功文件自动入成果库。

## 5. 音频裁剪与拼接

### 工作区与排序

从系统文件选择器或内部成果库添加多首歌曲。每首卡片有名称、原始时长、剪辑后时长、左侧拖动柄、裁剪、上移/下移。

长按左柄排序，靠近列表边缘自动滚动，松手确认并自动保存，取消恢复原序；同时保留上移/下移按钮。排序不改变音频内容。

### 按钮式单曲裁剪

传统按钮式剪切，接近带剪切能力的音乐播放器，波形辅助而非主要交互，不要求学复杂时间轴。

常用按钮：播放/暂停、后退 5 秒、前进 5 秒、标记开始、标记结束。显示名称、当前播放时间、总时长、简洁波形、当前选区。

必须遵守的流程：
1. 用户播放，在不要的部分开始处按“标记开始”。
2. 播放不中断，在不要的部分结束处按“标记结束”。
3. 标记结束自动暂停，展示起点、终点和选区时长。
4. 可试听、精确调整或取消标记。
5. 按“删除这段”删除范围，剩余片段立即合拢。
6. 删除后保持暂停，位置在新接缝处，提供“试听连接处”“撤销”“继续播放”。
7. 可以重复删除多个不连续区间。全程非破坏性，不修改原始文件。

更多编辑或底部面板提供分割、删除选区、仅保留选区、多次剪切、撤销、重做、恢复删除内容、原曲试听、编辑结果试听、接缝试听、时间数字输入、起止点 ±0.1 秒、当前播放位置设为起点/终点。不要同时展示全部按钮。

### 时间模型

使用非破坏性片段：保留源引用与原始起止时间。使用足够精确的整数时间（微秒），避免浮点累积。能计算成品时长、将成品时间映射回原曲、跨片段删除、恢复内容、接缝定位、重开还原。禁止反复修改原始 MP3 来存剪辑状态。

### 波形与试听

从真实音频分析峰值、RMS 等适当数据；多级分辨率、缩放、平移、定位，正确显示静音，避免几乎直线，不制造虚假音量变化，不阻塞主线程。删除后编辑波形立即合拢。可保留高级手势，但不得强制拖波形剪辑。

使用 Media3 ExoPlayer，支持原曲与编辑结果试听。编辑试听严格按保留片段顺序，不得播放完整原曲冒充编辑。接缝试听连续播放连接点前后。某些格式/播放器无法与最终 MP3 完全一致时明确限制，不宣称所有情况下完全相同。

### 拼接导出与响度

按歌曲顺序拼接，允许单曲导出，默认 MP3。默认名称“拼接的歌曲”，名称框不显示扩展名。Bottom Sheet 展示文件名、格式、响度均衡、歌曲数、预计时长、开始导出。

响度均衡默认开，可关闭；使用 FFmpeg loudnorm，每首歌曲分别进行歌曲级分析与处理，正确执行分析和处理流程，减小歌曲间主观响度差。不得修改源文件、加入额外自动增强或动态压缩。未做响度处理的普通试听不能冒充已均衡成品。

## 6. 成果库与文件交付

只自动收录视频转换和拼接导出成果；普通导入歌曲不自动收录。分类：全部、视频转换、拼接成果。每个成果支持试听、重命名、分享、另存、添加到拼接、删除。

正式成果使用应用内部持久存储，不依赖临时缓存。先写临时文件，成功完成并验证文件存在后再正式登记；失败/取消无伪成功记录。同名创建新副本，不覆盖。

导出成功留在当前模块，显示成功 Bottom Sheet，含试听、另存到 U 盘、查看成果库；关面板不删除成果。

U 盘另存使用 SAF 选择位置，是复制不是移动，尽可能记住最近位置；首次或授权失效可重选。未连接给明确提示，失败不删内部成果，不覆盖外部文件，不承诺未授权写任意目录。无法判定是否拔盘时准确描述位置不可用/授权问题，不伪造检测结论。

删除成果默认同时删除内部实体，防止积累；若最近项目仍引用，可移除成果记录但暂留实体，项目释放引用后安全清理。外部 U 盘副本不受影响。临时文件、取消残留、无引用工作文件及时清理。

## 7. 唯一最近项目

仅一个最近剪辑项目，自动保存列表、顺序、每曲片段、文件引用和必要导出设置，使用 Kotlinx Serialization；退出可继续。不加入复杂项目管理器、文件夹、版本系统。正确处理 URI 权限、文件有效性，长期需要时做受控内部副本；不得因成果/缓存清理破坏有效项目。

允许阅读源码、目录、类型/API明显错误检查、资源引用、数据结构、Git diff；每阶段最多运行一次 git diff --check。不要求每小功能大量单测。

每阶段分别记录已写源码、未接通、未编译、潜在问题、待本地验证；不得将已写代码当已验证可运行，不虚构结果。关键阶段由用户 Android Studio 构建和设备检查，针对用户具体错误修复，不展开无关测试或重构。阶段 8 同样遵守。

## 14. 第二轮 UI 精修（2026-11-14，覆盖首轮的密度与状态呈现）

用户已在手机查看上一轮并提供四张实机截图：成果库空态、视频空态、已选视频及转换命名面板、无歌曲裁剪器。本轮以真实截图反馈为依据，只调整 Compose/主题/UI 状态呈现，不推进业务或阶段4，不换新皮肤。

- 全局保持紫蓝深浅主题，页面标题约24sp、卡片16–18sp、正文14–16sp、辅助12–14sp，页面左右16dp。收紧标题字重/行高和按钮内容间距，仍保证48dp触摸；明确区分禁用和辅助文字。不通过更大图标/圆角/卡片边距填空白，不加复杂动画。
- 成果库保留标题和三分类，柔和统一 Chip。全库为空只保留音频图标/标题/一句说明和“去制作音频”导航现有首页；筛选为空但已有其他成果时引导查看全部。已有成果直接用紧凑文件列表，保留试听及所有菜单入口，不增加装饰卡。
- 视频已有文件时：并排两个添加按钮；文件项图标40–48dp、名称和移除同一行，时长/大小紧随名称，长名最多两行省略。默认待转换不重复展开状态行；有实际进度/失败/非默认状态才展开相应内容，卡片高度由内容决定。数量只保留一次，列表独立滚动。
